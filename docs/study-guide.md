## 0. 30초 요약과 학습 목표

**과제.** 반도체 패턴(홀 구조)을 위에서 찍은 SEM 영상 1장(48×72 픽셀)을 입력으로,
같은 크기의 **픽셀별 깊이 맵**을 출력한다. 평가는 실제 SEM 영상 25,988장에 대한 RMSE.

**난제.** 픽셀 정답(Depth Map)은 **시뮬레이션** 영상에만 있고, **실제** 영상에는
site(촬영 위치)당 평균 깊이 숫자 1개만 있다. 즉 "시뮬레이션으로 배워서 실제에 적용"하는
sim-to-real 문제이며, 두 도메인은 외형·라벨 인코딩·라벨 분포 세 겹으로 어긋나 있다.

**결과.** 순수 시뮬레이션 학습 8.000(제출 172팀 중 118위) → 약지도 EM-아핀 5.325(39위)
→ 프레임 평균 입력 5.113(35위) → 3멤버 앙상블+TTA **4.597 / 4.618 (Public/Private),
제출 172팀 중 26위 (등록 790명)**.

**이 문서를 다 읽고 나면 설명할 수 있어야 하는 것**

- 왜 반도체 공정에서 "홀 깊이"를 인라인으로 재고 싶어 하는지, 기존 계측 기법의 한계는 무엇인지
- SEM 영상에서 밝기가 깊이 정보를 담는 물리적 이유(이차전자, 에지 효과)
- 이 데이터의 3중 어긋남과, 그것이 표준 도메인 어댑테이션 기법을 실패하게 만든 이유
- 약지도 EM-아핀이 무엇을 풀었고 어떻게 동작하는지(수식·코드 수준)
- cal-proxy 지표의 유효 구간과 사각지대, 그리고 self-training이 왜 LB를 악화시켰는지
- itr-평균 입력이 왜 "밝기를 보존하는 정합"인지, 블러 σ를 어떻게 측정했는지
- 앙상블에서 질>양이 성립한 근거
- 상위권(견본 검색) 패러다임의 원리와, 재현에서 무엇이 성립하고 무엇이 성립하지 않았는지

## 1. 반도체 도메인 배경 — 왜 이 문제가 존재하는가

### 1.1 공정 흐름에서 계측이 서는 자리

반도체 전공정(front-end)은 웨이퍼 위에 **증착(deposition) → 노광(lithography) →
식각(etch) → 세정 → 이온주입/열처리 → CMP** 같은 단위 공정을 수백 번 반복해 층을
쌓는 과정이다. 각 단위 공정 뒤에는 "방금 만든 구조가 설계대로 됐는가"를 확인하는
**인라인 계측(in-line metrology)** 과 **결함 검사(inspection)** 단계가 있다.

- 계측(metrology)은 **치수를 잰다**: 선폭(CD, critical dimension), 두께, 오버레이,
  그리고 이 프로젝트의 주제인 **깊이/프로파일**.
- 검사(inspection)는 **결함을 찾는다**: 파티클, 브리지, 미개방(not-open) 등.
- 잰 값은 SPC(통계적 공정 관리) 차트에 올라가 공정 이탈을 잡고, 다음 공정의 조건을
  보정(APC)하는 데도 쓰인다. 계측이 늦거나 부정확하면 불량 웨이퍼가 수십 공정을
  더 진행한 뒤에야 발견되므로, **계측의 속도·정확도가 곧 수율과 비용**이다.

SK하이닉스 JD의 DMI(Defect & Metrology Inspection)가 바로 이 자리에 있는 직무다.

### 1.2 왜 "깊이"가 중요해졌나 — 3D 구조와 고종횡비(HAR) 식각

미세화의 한계를 소자의 **수직 적층**으로 돌파하면서 계측 대상이 2D에서 3D로 바뀌었다.

| 구조 | 무엇을 파는가 | 왜 깊이가 관건인가 |
|---|---|---|
| **V-NAND 채널 홀** | 100단 넘게 쌓은 ON(산화막/질화막) 적층을 한 번에 관통하는 홀 (종횡비 수십:1) | 바닥까지 뚫리지 않으면(under-etch) 채널이 끊겨 셀 전체가 불량. 너무 파면(over-etch) 아래 층 손상 |
| **DRAM 커패시터** | 전하를 저장할 깊은 원통형 홀 | 깊이가 곧 정전용량(capacitance) — 깊이 편차가 리프레시 특성 편차로 직결 |
| **콘택/비아** | 층간 배선 연결 홀 | 미개방 시 회로 단선 |

고종횡비(High Aspect Ratio, **HAR**) 식각은 플라즈마 건식 식각으로 수행되며, 깊어질수록
이온·라디칼이 바닥까지 도달하기 어려워 식각 속도가 떨어지고(ARDE, aspect-ratio
dependent etching), 보잉(bowing, 중간이 볼록하게 파임)·트위스팅·테이퍼링 같은 프로파일
이상이 생긴다. 그래서 **식각 깊이와 프로파일을 웨이퍼 전면에 걸쳐 빠르게 관리**하는
것이 HAR 공정의 핵심 과제다.

### 1.3 기존 깊이 계측 기법과 그 한계

| 기법 | 원리 | 장점 | 인라인 깊이 계측으로서의 한계 |
|---|---|---|---|
| **단면 TEM/STEM** | FIB로 시편을 잘라 단면을 투과전자현미경으로 관찰 | 원자 수준 해상도, 직접 관측 | **파괴적**, 시편 준비 수 시간, 웨이퍼당 몇 점 샘플링 — 전수·인라인 불가 |
| **AFM** | 탐침이 표면을 훑어 높이 측정 | 비파괴, 정밀 | 느리고, **HAR 홀에는 탐침이 바닥까지 못 들어감** |
| **OCD(scatterometry)** | 광 반사 스펙트럼을 기하 모델로 피팅 | 빠르고 비파괴, 인라인 표준 | 스팟(수십 µm) 내 **평균값**, 기하 모델과 라이브러리가 선행되어야 함, 개별 홀 정보 없음 |
| **CD-SEM** | 전자빔 주사, 이차전자 영상 | 인라인에 이미 대량 설치, 빠름, 비파괴, 개별 홀 관측 | 출력이 **2D 영상** — 깊이를 직접 주지 않음 |

이 표의 마지막 줄이 이 과제의 동기다. **CD-SEM은 이미 라인에 깔려 있고 개별 홀을 보지만
깊이를 주지 않는다. 그 2D 영상 안에 사실은 깊이 정보가 물리적으로 새겨져 있으니, 그것을
AI로 복원하면 추가 장비 없이 인라인 3D 계측이 열린다.** 삼성이 이 대회를 낸 이유이며,
JD가 말하는 "AI/DT를 활용한 계측 혁신"의 구체적 예시다.

### 1.4 시뮬레이션 데이터는 왜 존재하나

실제 홀의 픽셀별 깊이 정답을 얻으려면 홀마다 단면을 잘라야 하니(TEM) 대량 확보가
불가능하다. 대신 **전자-물질 상호작용을 몬테카를로로 시뮬레이션**하면(전자 궤적을
확률적으로 추적하는 시뮬레이터, 학계의 CASINO 같은 도구가 대표적) 임의의 3D 구조에
대해 "이 구조를 SEM으로 찍으면 이런 영상이 나온다"를 만들 수 있고, 구조를 알고
있으니 픽셀별 깊이 정답이 공짜다. 문제는 시뮬레이션이 실제 장비·시편을 완벽히 흉내
내지 못한다는 것 — 이것이 sim-to-real 갭이며, 이 프로젝트의 본체다.

## 2. SEM의 물리 — 영상이 깊이를 담는 원리

### 2.1 SEM이 영상을 만드는 방식

1. 전자총에서 나온 **일차전자(primary electron) 빔**을 시편 위에서 래스터 주사한다.
   CD-SEM은 시편 손상과 대전을 줄이려 수백 V~1 kV급 저가속 전압을 쓴다.
2. 빔이 닿은 지점에서 여러 신호가 나온다. 영상에 주로 쓰는 것은
   - **이차전자(SE, secondary electron)**: 시편 원자에서 튀어나온 저에너지(<50 eV)
     전자. 에너지가 낮아 표면 몇 nm 안에서 생긴 것만 탈출 → **표면 형상에 민감**.
   - 후방산란전자(BSE): 일차전자가 튕겨 나온 것. 조성(원자번호)에 민감.
3. 검출기(Everhart–Thornley 등)가 각 주사 지점의 SE 개수를 세어 픽셀 밝기로 기록한다.
   **밝기 = 그 지점에서 검출기까지 도달한 SE 수.**

### 2.2 왜 깊은 홀은 어둡고 테두리는 밝은가

- **홀 바닥의 어두움(shadowing)**: 바닥에서 발생한 SE는 좁고 깊은 벽을 거슬러 올라와야
  검출기에 닿는다. 깊을수록 벽에 흡수되는 비율이 커져 **깊은 홀일수록 바닥이 어둡다**.
  홀 벽에 전하가 쌓이면(charging) 저에너지 SE가 더 붙잡혀 이 효과가 심해진다.
- **에지 효과(edge effect)**: 경사면·모서리에서는 상호작용 부피가 표면과 더 많이
  겹쳐 SE 탈출이 늘어난다 → **홀 테두리가 밝은 링**으로 보인다.

이 두 효과 때문에 top-down 영상에 깊이 정보가 실린다. 그리고 이 데이터에서 그 관계는
**site 평균 밝기 ↔ 평균 깊이 상관 r = −0.977**로 거의 결정론적이었다
(그림: `report/figures/04_brightness_vs_depth.png`). 이 한 숫자가 프로젝트의 여러
결정을 좌우한다 — **밝기는 노이즈가 아니라 신호다.**

### 2.3 노이즈와 프레임 평균

SE 검출은 전자를 세는 과정이므로 **푸아송(shot) 노이즈**가 지배적이다. 이를 줄이는
장비의 표준 방법이 **프레임 적산(frame integration/averaging)** — 같은 자리를 여러 번
주사해 평균 내면 노이즈가 1/√N으로 준다. 실제 CD-SEM 영상이 시뮬레이션보다 "부드러운"
이유가 이것일 수 있다는 가설이 나중에 E6(itr-평균 입력)의 근거가 된다. 시뮬레이션은
구조당 노이즈 실현(realization)을 2장(`itr0`, `itr1`) 제공하는데, 그 둘의 평균
|차|는 9.89±0.74(0–255 스케일)였고, 실제 영상의 같은 site 내 영상 간 |차|도 ≈10으로
같은 수준이었다 — 실제 데이터에도 "반복 촬영" 구조가 있다는 뜻이다.

## 3. 문제 정의와 데이터의 실체

### 3.1 대회 규격

- 대회: 2022 Samsung AI Challenge (3D Metrology), Dacon 235954
- 입력: SEM 영상 48×72 8-bit grayscale (배열 (72, 48)). 출력: 같은 크기 Depth Map PNG.
- 평가: RMSE. Public 20% / Private 80%. 제출은 Depth PNG들을 zip으로.
- 규칙: 공개 사전학습 모델·외부 데이터 허용, 테스트 데이터를 학습에 쓰면 실격.

### 3.2 데이터 레이아웃(실측)

```
data/raw/
  simulation_data/SEM/Case_{1..4}/{80..84}/<base>_itr{0,1}.png   # 173,304장
  simulation_data/Depth/Case_{1..4}/{80..84}/<base>.png          # 86,652장
  train/SEM/Depth_{110,120,130,140}/site_XXXXX/SEM_XXXXXX.png    # 60,664장
  train/average_depth.csv                                        # 2,059행 (site 단위)
  test/SEM/XXXXXX.png                                            # 25,988장
```

| 데이터 | 규모 | 라벨 |
|---|---|---|
| 시뮬레이션 | 구조 21,663종 × 4 Case × 2 itr = SEM 173,304장 | **픽셀별** Depth 86,652장 |
| 실제 train | 2,059 site × ~29장 = 60,664장 | site당 **평균 깊이 1개** |
| 실제 test | 25,988장 | 없음 |

### 3.3 데이터를 뜯어서 알아낸 사실들 (설계를 바꾼 순서대로)

**(a) 동일 구조가 4개 Case에 반복된다 — 누수 함정.** base name 21,663개가 Case_1~4에
정확히 한 번씩 등장. 케이스나 파일 단위로 train/val을 나누면 같은 구조가 양쪽에 들어가
검증 점수가 부풀어 오른다. → **구조 이름(group_id) 단위 그룹 스플릿**을 설계의 전제로
삼고 테스트로 고정했다(`split_pairs`).

**(b) 라벨은 site 단위다.** `average_depth.csv`는 2,059행(헤더 "0,1", 키
`depth_<bucket>_site_<id>`), 이미지 단위가 아니다. site 폴더의 ~29장이 같은 라벨을
공유한다(fan-out). 부수 발견: 주최측이 실수로 넣은 Jupyter 체크포인트 파일 1장(60,665 vs
60,664), 대회 페이지의 "시뮬레이션 259,956장"은 SEM+Depth 합계.

**(c) 3중 어긋남** (EDA로 정량화):

1. **외형 갭**: sim 픽셀 μ/σ 99.9/57.8 (거칠고 날카로운 노이즈) vs real 115.6/65.8
   (부드러움). 온건하지만 실재.
2. **라벨 인코딩 불일치**: sim Depth 픽셀은 **작을수록 깊음**(홀 내부 저값), real
   `average_depth`는 **클수록 깊음**(Depth_140 폴더 평균 ≈ 138). 밝기와의 상관 부호로
   판별했다. 둘을 잇는 사상은 미지수.
3. **라벨 시프트**: sim depth 맵의 영상 평균은 111±7.5로 한 덩어리인데, real은
   108.7/118.6/128.2/138.2(±1.5) 4군집. sim은 real 깊이 범위의 가운데만 커버한다 →
   sim만으로 배우면 깊은 시편에서 계통적 과소 예측.

**(d) real train ↔ test 분포는 사실상 동일** (115.6/65.8 vs 115.6/65.9). 제출 없이
real train으로 계산하는 프록시가 test를 대변할 수 있다는 근거.

**(e) sim 버킷 80~84는 깊이가 아니다.** 버킷별 depth 평균이 전부 111~112. 파티션 또는
조건 변수로 추정, 성능에 무관.

**(f) GT 구조의 완전 해독 (확장 트랙에서).** sim depth 맵의 배경은 Case별 상수
140/150/160/170(픽셀의 ~51%), 홀 바닥은 30. `배경 − 바닥 = 110/120/130/140` = real의
Depth 버킷 폴더명 → **real 버킷 ↔ sim Case가 1:1 대응**. GT의 상위 2개 값(배경+바닥)이
픽셀의 ~60%를 차지하므로 문제의 절반 이상은 "분류+분할" 성격이다.

**(g) `average_depth`의 정체.** 1위 발표자료와 교차 검증한 결과, crop 밖 마진까지 포함한
플레이트 평균(케이스별 마진 규칙 존재). 아핀 인코딩을 고정하지 않은 EM 설계(§4.3)가
옳게 동작한 이유가 여기서 설명된다.

## 4. 프로젝트 설계 — 무엇을, 왜 그렇게 결정했나

### 4.1 접근법 선택: 3단계 정공법

후보는 세 갈래였다.

| 후보 | 개요 | 판단 |
|---|---|---|
| **A. 3단계 정공법** | sim 지도학습 → 도메인 갭 브리징(입력 정렬·약지도·self-training) → 앙상블 | **채택.** 각 단계가 ablation 축이 되어 "무엇이 왜 효과 있었나"를 설명 가능. 계측 실무 서사(캘리브레이션, 검증)와 정합 |
| B. GAN 도메인 변환 | CycleGAN으로 sim→real 변환 후 지도학습 | 학습 불안정·검증 어려움. 소규모 검토만 하고 근거를 남기기로 |
| C. 견본 검색 | 테스트 영상과 가장 닮은 sim 구조의 GT를 출력 | 처음엔 고려 밖. 상위권이 실제로 쓴 방식임을 나중에 알게 됨(§6) |

A안의 핵심 논리: **픽셀 형상은 sim에서 배우고(픽셀 GT가 있으니), real에서 부족한 것
— 평균 수준(라벨 시프트)과 외형 — 만 real의 약한 라벨과 물리 가설로 메운다.**

### 4.2 검증 체계: 제출 없이 무엇을 알 수 있는가

리더보드 제출은 하루 10회 한도이고, 무엇보다 **real 픽셀 정답이 없으니 진짜 점수는
리더보드만이 안다**. 그래서 로컬 지표 두 축을 설계하고, 제출할 때마다
(sim-val, cal-proxy, LB) 3개조를 기록해 로컬 지표의 예측력 자체를 검증했다.

| 지표 | 정의 | 잰다 | 못 잰다 |
|---|---|---|---|
| **sim hold-out RMSE** | 구조 단위로 뗀 sim 검증셋의 픽셀 RMSE(0–255) | 픽셀 형상 학습 여부 | real 전이 |
| **raw proxy** | real train 6만 장에서 `mean(pred)·255 vs avg_depth` RMSE | — (인코딩이 달라 그대로는 의미 없음) | — |
| **cal-proxy** | `avg_depth ≈ α + β·mean(pred)`를 최소제곱 적합한 뒤 잔차 RMSE + 상관 | **평균 수준의 real 전이력** (인코딩 미지수 우회) | **픽셀 형상 오차** |
| **LB** | 제출 | 전부 | 하루 10회, 정보 병목 |

cal-proxy의 아이디어: 예측 맵의 평균과 실제 평균 깊이 사이에 미지의 아핀이 있어도,
"직선을 그었을 때 점들이 얼마나 직선에 붙는가"는 잴 수 있다. 상관이 높고 잔차가
작으면 모델이 real 영상의 **깊이 순서와 간격**을 이미 알고 있다는 뜻이다.

이 지표의 **사각지대**(평균이 풀린 뒤로는 픽셀 오차를 못 봄)는 설계 시점의 우려였고,
E3에서 실험으로 확정된다(§5.5). 그 뒤부터 제출을 "가설 검증 단위"로만 썼다.

### 4.3 핵심 메커니즘 ① 약지도 EM-아핀 (미리 이해해 두기)

문제: real 라벨 `avg`(물리 스케일, 클수록 깊음)와 모델 출력의 평균 `m`(sim 픽셀 인코딩,
작을수록 깊음) 사이의 관계 `avg ≈ α + β·m`에서 (α, β)를 모른다. 잘못 추측해서 고정하면
모델이 틀린 목표를 향해 간다.

해법: (α, β)를 **모델과 번갈아 추정**한다(EM 구조).

```
매 epoch:
  E-step  real train 샘플 8,192장에 대해 현재 모델의 m을 구하고
          (α, β) = polyfit(m, avg, 1)   # 폐형 최소제곱, 학습 아님
  M-step  loss = pixel_loss(sim) + λ · | α + β·m(real) − avg | / 255
```

```python
# src/semdepth/finetune.py 핵심부
with torch.autocast(device, dtype=torch.bfloat16, enabled=tr["amp"]):
    l1 = pixel_loss(model(xs), ts)                       # sim: 픽셀 형상 앵커
    mean255 = model(xr).mean(dim=(1, 2, 3)) * 255.0      # real: 예측 맵 평균
    lreal = (a + b * mean255 - ar).abs().mean() / 255.0  # 아핀 사상 후 라벨과 비교
    loss = l1 + lam * lreal
```

역할 분담: **sim L1 항이 픽셀 형상을 고정**하고(이게 없으면 모델이 평균만 맞추는
상수 맵으로 퇴화), **real 항이 예측 대역을 라벨 분포(4군집)로 벌린다**. 퇴화 방지
장치: 기울기 |β|가 0.1 아래로 떨어지는 재적합은 무시(degenerate-slope guard), epoch 0의
재적합은 초기 가중치 점수이므로 체크포인트로 저장하지 않음.

### 4.4 핵심 메커니즘 ② 밝기를 보존하는 정합 (itr-평균 + 계측된 블러)

외형 갭을 줄이는 표준 방법(밝기 정규화, 밝기·대비 랜덤화)은 **절대 밝기를 지운다**.
그런데 이 문제에서 절대 밝기는 깊이 신호 그 자체(r=−0.977)다. 그래서 밝기를 건드리지
않고 노이즈 결만 바꾸는 방법이 필요했다.

- **itr-평균 입력**(`input_mode: itr_mean`): 학습 입력을 `mean(itr0, itr1)`으로. 평균은
  밝기 기대값을 보존하면서 노이즈만 1/√2로 줄인다 = 실제 장비의 프레임 적산과 같은 연산.
- **스펙트럼 캘리브레이션 블러**: itr-평균 뒤 남는 부드러움 차이를 가우시안 블러로
  메우되, σ를 감으로 고르지 않고 **real 영상과 sim(itr-평균+블러 σ) 영상의 방사형 파워
  스펙트럼이 가장 가까워지는 σ를 탐색** → σ* = 0.7. E9는 [0.5, 0.9] 지터로 학습.

### 4.5 모델과 학습 레시피

- **UnetTimm** (`src/semdepth/model.py`): timm 인코더(`features_only=True, in_chans=1`,
  ImageNet 사전학습) + 직접 구현한 U-Net 디코더(업샘플 → skip concat → conv×2). 입력을
  32의 배수로 replicate 패딩했다가 잘라내므로 48×72 같은 임의 크기를 받는다. 출력은
  sigmoid로 [0,1] (=0–255 깊이).
- 인코더: resnet34(기본), convnext_tiny(다양성용), convnext_small(E12).
- 손실: L1(기본). LB가 RMSE이므로 l2/l1l2 옵션도 추가(E12).
- 베이스 학습: 40 epoch, batch 256, AdamW lr 3e-4, cosine, bf16 autocast, flip 증강.
  약지도 파인튜닝: 베이스 체크포인트에서 8 epoch, lr 1e-4, λ=1.0, 재적합 샘플 8,192.
- 추론: 멤버별 예측 평균(앙상블) + 좌우 flip TTA, uint8 PNG → zip.

### 4.6 실험 인프라 (재현성)

## 5. 진행 과정 — 실험이 흘러간 순서와 중간 결과

각 실험은 "가설 → 방법 → 로컬 결과 → (제출 시) LB → 해석 → 다음 결정"으로 읽는다.
로컬 지표 표기: **cal-proxy / corr / sim-val**.

### 5.1 S1 — 순수 시뮬레이션 지도학습 베이스라인

- 가설: 우선 sim만으로 픽셀 형상을 배우고, 도메인 갭이 점수를 얼마나 지배하는지 잰다.
- 방법: resnet34 U-Net, 40 epoch(파일럿 1 epoch로 속도 실측 ≈ 43초/epoch 후 스케줄 결정).
- 로컬: sim-val **2.085** / cal-proxy 5.37 / corr 0.875 (raw proxy 11.9, α=−64.3, β=1.65).
- LB: **8.000 → 118위/172**.
- 해석: sim 안에서는 2.1인데 real에서는 8.0 — **도메인 갭이 점수를 지배**한다. 그리고
  β≈1.65(≠−1)는 두 인코딩의 관계가 단순 부호 반전이 아님을 시사 → 아핀을 추측하지
  말고 데이터로 추정해야 한다.

### 5.2 E0 — 전역 아핀 입력 정렬 (재학습 없음) ❌

- 가설: real 입력의 강도 분포를 sim 분포로 옮기면(`x' = (x−μ_r)/σ_r·σ_s + μ_s`, 영상 간
  순서 보존) 베이스라인이 그대로 더 잘 전이한다.
- 결과: cal-proxy 5.37 → **6.50**, corr 0.875 → 0.810. 기각(미제출).
- 해석: 밝기의 절대 위치를 옮기자 깊이 순서 정보가 왜곡됐다. 첫 번째 "밝기=신호" 증거.

### 5.3 E1 — 외형 랜덤화 (밝기·대비·블러·노이즈 지터 학습) ❌

- 가설: 표준 sim-to-real 처방대로 sim 입력에 외형 지터를 주면 외형 불변 특징을 배운다.
- 결과: sim-val 4.64(악화), cal-proxy **7.13**, corr 0.766. 기각(미제출).
- 해석: 밝기에 불변하게 만들었더니 **깊이 신호를 스스로 지웠다**. 두 번째 증거.
  → 이후 모든 정합은 "밝기 보존"을 제약 조건으로 삼는다. E2는 E1이 아니라 S1 체크포인트
  위에서 시작하기로 결정.

### 5.4 E2 — 약지도 EM-아핀 파인튜닝 ✅ (핵심 기여 ①)

- 방법: §4.3. S1 체크포인트에서 8 epoch.
- 로컬: cal-proxy 5.37 → **1.84**, corr 0.875 → **0.986**, sim-val 2.64(소폭 희생).
- LB: **5.325 → 39위** (−2.68점).
- 해석: 라벨 시프트(평균 수준) 문제가 사실상 해결. **로컬 게이트 ↔ LB의 상관이 처음
  확인**된 시점 — 이후 로컬 지표를 믿고 제출을 아낄 근거가 생겼다.

### 5.5 E3 — Self-training (pseudo 라벨) ❌ — 가장 값진 네거티브

- 가설: E2 모델로 real train 6만 장의 pseudo depth 맵을 만들어 sim과 섞어 재학습하면
  real 픽셀 형상까지 배운다.
- 로컬: cal-proxy 1.84 → **1.61**, corr **0.989**, sim-val 2.64 → **2.34** — 전부 개선.
- LB: **5.628 / 5.609** — E2(5.325)보다 **악화**.
- 해석 두 가지:
  1. **확증 편향**: pseudo 라벨은 모델 자신의 예측이라 real 픽셀 형상의 계통 오차가
     정답으로 재학습된다.
  2. **지표의 사각지대 확정**: 평균이 맞은 뒤에는 cal-proxy가 픽셀 오차를 전혀 못 본다.
     이 실험 이후 "로컬 全개선 = 제출 근거"라는 등식을 버리고, 제출을 가설 단위로 아꼈다.

### 5.6 E4a — convnext_tiny 베이스 (앙상블 다양성 준비)

- sim-val 2.247(seed 43). 당장 제출용이 아니라 나중에 다른 레시피 위에 얹을 멤버 후보.

### 5.7 E5 — E1 특징 + 약지도 ❌

- 가설: E1의 외형 강건 특징 위에 약지도로 평균만 복원하면 두 장점을 합칠 수 있다.
- 결과: cal-proxy **5.33**에서 정체(sim-val 5.28). 기각.
- 해석: 한 번 버린 밝기 경로는 짧은 파인튜닝으로 복원되지 않는다. 세 번째 증거 —
  E0·E1·E5 세 실패가 **"밝기는 노이즈가 아니라 신호"** 하나로 수렴했다.

### 5.8 E6 — itr-평균 입력 + 약지도 ✅ (핵심 기여 ②)

- 가설: real이 부드러운 이유가 프레임 적산이라면, sim 입력을 `mean(itr0, itr1)`으로
  바꾸면 밝기를 훼손하지 않고 real의 look에 접근한다(§2.3, §4.4).
- 로컬 선행 검증: 약지도 파인튜닝 **시작 시점(epoch 0)** 의 cal-proxy가 5.41 → **3.83**
  — 재학습 전에 이미 전이력이 좋아졌다. 가설이 로컬에서 먼저 성립.
- 파인튜닝 후: cal-proxy 1.93 / corr 0.985 / sim-val 3.09(sim 안에서는 오히려 나빠짐 —
  sim-val이 real 성능의 대리가 아님을 다시 보여줌).
- LB: **5.113 / 5.110 → 35위** (−0.21점). 픽셀 수준의 개선.

### 5.9 E7 — itr-평균 + 블러만 지터 (중립, 앙상블 멤버)

- 밝기·대비·노이즈 없이 **블러만** [0, 1.0] 지터. 파인튜닝 전 전이 3.53(더 좋음)이지만
  후 cal-proxy 2.00. 단독으로는 E6 이하 — 다양성 멤버로 보관.

### 5.10 E4b/E4c — convnext_tiny에 E6 레시피

- E4b(itr-평균 베이스) sim-val 2.306 → E4c(약지도) cal-proxy **1.58**, sim-val 2.46.
  **최강 단일 멤버**. 아키텍처 다양성(CNN vs ConvNeXt) 확보.

### 5.11 E8 — 3멤버 앙상블 + flip TTA ✅ 최종 최고

- 구성: E6b(r34 itr-평균) + E7b(r34 +블러) + E4c(convnext) 동일 가중 평균, 좌우 flip TTA.
- 로컬(샘플 앙상블): cal-proxy 1.96 / corr 0.984.
- LB: **4.597 / 4.618 → 26위** (최고 단일 5.113 대비 −0.52).
- 해석: 가설이 서로 다른 멤버(입력 정합 방식·아키텍처)의 오차가 상쇄됐다.

### 5.12 E9·시드 클론 — 계측된 블러와 멤버 확충

- E9: 방사형 파워 스펙트럼 매칭으로 σ*=0.7 계측 → [0.5, 0.9] 지터. cal-proxy 1.92,
  sim-val 3.37. 중립.
- 시드 클론: e6b_s44(2.06), e4c_s45(1.63). 앙상블 확장 재료.
- 부수 실험: **site 내 예측 불일치 지표**(같은 site의 ~29장 예측 표준편차). 라벨 없이
  안정성을 재지만 **LB 순서를 재현하지 못했다** — self-training 모델은 "안정적으로
  틀릴" 수 있다. 안정성 ≠ 정확성. 진단용으로만 보관.

### 5.13 E10 — 6멤버 그랜드 앙상블 ❌

- E8 3멤버 + E9b + 시드 클론 2개, 동일 가중.
- LB: **4.657 / 4.677** — E8보다 후퇴.
- 해석: 약한 멤버가 동일 가중 평균을 희석한다. **앙상블은 질 > 양.** E11(최강 3:
  convnext×2 + E6b)은 zip만 만들고 미제출로 남김.

### 5.14 E12 — RMSE 정렬 손실과 스케일업 (회귀 경로의 마지막 시도)

- l1l2 손실 + 16 epoch 파인튜닝, convnext_small. e12d cal-proxy **1.52**(최고 회귀
  멤버)지만, cal-proxy가 이미 변별력을 잃은 구간이라 LB 검증 없이는 판단 불가.
  회귀 경로가 수확 체감에 들어갔다는 판단으로 확장 트랙(§6)으로 전환.

### 5.15 진행 흐름 한눈에

```
S1 8.000 (118위)
 ├─ E0 전역 정렬 ❌      ┐
 ├─ E1 외형 랜덤화 ❌    ├─ "밝기 = 신호" 수렴
 └─ E5 E1+약지도 ❌      ┘
E2 약지도 EM-아핀 5.325 (39위)   ← 평균 수준 해결
 └─ E3 self-training ❌ 5.628    ← 프록시 사각지대 확정
E6 itr-평균 5.113 (35위)          ← 픽셀 수준, 밝기 보존 정합
 ├─ E7 +블러, E9 σ*=0.7, E4c convnext  (멤버)
E8 3멤버+TTA 4.597 (26위)         ← 최종 클레임
 └─ E10 6멤버 4.657 ❌            ← 질 > 양
```

## 6. 확장 트랙 — 상위권 솔루션 리버스 엔지니어링

26위 이후 "왜 상위권은 1~2점대인가"를 알기 위해 공개된 1위 솔루션(LB 1.22)을 분석·재현했다.

### 6.1 1위의 패러다임: 회귀가 아니라 견본 검색(re-identification)

1. CycleGAN으로 sim 86,652장을 real 스타일로 변환해 **라이브러리**를 만든다.
2. 테스트 영상을 케이스(=깊이 버킷) 4-way 분류한다(effnet-b0, real train의 버킷 폴더명이
   라벨 — GAN 불필요).
3. 테스트 영상을 per-image 표준화한 뒤, 같은 케이스의 라이브러리 전체와 **코사인
   유사도(±2px 순환 시프트 25조합의 max)** 를 계산해 top-1 매치를 찾는다.
4. **매치된 sim 구조의 GT depth 맵을 그대로 출력**한다(KNN=1).

전제: 테스트 영상이 sim 라이브러리와 **같은 구조 모집단의 재촬영**이라는 것. 이게
성립하면 회귀가 흐려 놓는 배경 상수(픽셀 51%)·홀 바닥까지 정확히 복원되므로 상한이
매우 낮아진다.

### 6.2 재현 결과: 성립한 것과 성립하지 않은 것

| 단계 | 결과 |
|---|---|

### 6.3 결론과 남긴 것

- 서로 다른 랭커 3종이 동일한 **~6.3**에 수렴하고 라이브러리 내부 플로어가 2.0인 점을
  합치면, **현 채점 환경에서 real test의 GT는 어떤 라이브러리 견본과도 평균 ~6.3
  거리** — 견본 복사 방식의 상한이며, 회귀(4.597)가 이를 상회하는 이유.
- 공개 1.22와의 간극은 로컬에서 검증 불가능한 요인(재현 밖 GAN 세부 또는 채점 GT의
  시점 차이)으로 남겼다. **재현되지 않은 것을 재현됐다고 쓰지 않는다.**
- 방법론적 수확 — **프록시의 함정 3연속**:
  1. 기하 정렬 프록시(중심 0.8px 일치)가 허위 안심이었음 → site-일관성이 진짜 오라클.
  2. "일관성" 오라클은 임베딩 붕괴(모두 같은 키로 수렴)에 속을 수 있음 → 다양성 항 추가.
  3. fp16 내적 오버플로우(dots ~7.8e7)·정밀도가 argmax를 뒤집음 → [0,1] 스케일 + float32.
  각각 테스트로 고정.
- 최종 판단: **E8 4.597(26위)을 메인 클레임**으로, 확장 트랙은 리버스 엔지니어링·검증
  서사로만 사용.

## 7. 어려웠던 점

**기술적**

1. **정답이 없는 도메인에서 무엇을 믿을 것인가.** real 픽셀 GT가 없어 LB만이 진실인데
   제출은 희소하다. 로컬 지표를 만들고, 그 지표가 언제까지 유효한지 실험으로 그어야 했다.
   E3에서 로컬 전부 개선·LB 악화를 겪고 나서야 사각지대가 확정됐다.
2. **표준 처방이 물리와 충돌.** 도메인 어댑테이션 교과서(정규화·랜덤화·self-training)를
   순서대로 시도했고 세 개가 연속 실패했다. 실패를 "튜닝 부족"이 아니라 "밝기=신호"라는
   물리로 해석해야 다음 성공(E2·E6·E9)이 나왔다.
3. **미지의 라벨 인코딩.** sim 픽셀과 real 평균 깊이의 관계를 모른 채 학습해야 했다.
   추측을 고정하지 않고 EM으로 번갈아 추정하는 구조가 답이었고, 나중에 `average_depth`
   의 정체(마진 포함 플레이트 평균)가 밝혀지면서 왜 그 설계가 맞았는지 설명됐다.
4. **누수의 위장.** 구조 반복은 데이터 검증 스크립트로 전수 대조하지 않았으면 "좋아
   보이는 검증 점수"로 끝까지 숨어 있었을 함정이다.
5. **수치 정밀도.** 검색 트랙에서 fp16 내적이 오버플로우·근사 동점 뒤집기로 순위를
   망쳤다. 큰 벡터의 유사도는 float32.
6. **하드웨어 호환.** RTX 5070 Ti(sm_120)는 cu128 빌드가 필요했고, DataLoader fork
   경고·PIL의 float 모드 블러 미지원 등 자잘한 벽이 있었다.

**진행 방식**

7. **제출 예산 관리.** 총 제출 10회 안에서 6회를 회귀 경로 가설 검증에, 3회를 확장 트랙에
   썼다. "로컬 게이트 통과 시에만 제출"이라는 규율이 없었으면 정보가 흩어졌을 것이다.
8. **멈출 때를 아는 것.** E12(cal-proxy 1.52)와 E11은 로컬로는 더 좋아 보였지만 지표가
   변별력을 잃은 구간이라 확인 수단이 없었다. 확장 트랙도 랭커 3종이 같은 값으로 수렴한
   시점에서 닫았다.

## 8. 중요한 점 — 이 프로젝트에서 가져갈 원칙

1. **데이터를 먼저 뜯어라.** 구조 반복(누수), site 단위 라벨, 인코딩 방향, 라벨 시프트,
   배경/바닥 상수 — 설계를 바꾼 사실은 전부 EDA·프로브에서 나왔다.
2. **물리를 제약 조건으로 써라.** r=−0.977은 "밝기를 건드리지 말라"는 제약이고,
   프레임 적산은 "itr을 평균하라"는 처방이었다. 도메인 지식은 서술이 아니라 설계에
   들어간다.
3. **모르는 파라미터는 고정하지 말고 추정하라.** EM-아핀의 폐형 재적합.
4. **지표의 유효 구간을 실험으로 그어라.** cal-proxy는 평균이 풀리기 전까지만 유효.
   sim-val은 real 성능과 무관할 수 있음(E6). 안정성 ≠ 정확성(site-일관성 지표).
5. **네거티브를 결론으로 만들어라.** E0·E1·E5가 한 문장으로 수렴했기에 이후 선택이
   빨라졌다. 실패는 기록하고 인용한다.
6. **제출은 실험이다.** 가설 1개 = 제출 1회. 결과를 (로컬, LB) 쌍으로 원장에 남긴다.
7. **앙상블은 선별이다.** 가설이 다른 소수의 강한 멤버 > 많은 멤버.
8. **캘리브레이션은 측정이다.** 블러 σ를 스펙트럼으로 잰다. 실무의 장비 캘리브레이션과
   같은 태도.
9. **상한부터 재라.** 검색 트랙에서 오라클 플로어(2.03)를 먼저 재고 랭커 갭을 정량화했다.
   "얼마나 좋아질 수 있는가"를 모르면 노력의 방향을 못 정한다.
10. **재현 가능하게 남겨라.** config 1개 = 실험 1개, 자동 원장, 합성 픽스처 테스트 56개.
    다른 사람이(또는 미래의 내가) 표를 다시 만들 수 있어야 결과다.

**계측 실무 관점으로 옮기면**

- 약지도의 (α, β)는 "이 장비·이 레시피"에 붙는 캘리브레이션 상수다. 장비 이관 시
  소량 라벨(TEM 크로스 캘리브레이션)로 재적합하는 절차가 필요하다.
- 잔여 오차(픽셀 형상)를 로컬에서 재지 못한 병목은 실무에서 소량의 실측 GT 셋으로 푼다.
- 48×72 U-Net 추론은 GPU 1장에서 초당 수천 장 — 인라인 적용의 병목은 모델이 아니라
  데이터 파이프라인이다.

<details><summary><b>Q1. 왜 CD-SEM 영상으로 깊이를 재려 하는가? TEM·AFM·OCD로는 왜 안 되나?</b></summary>

TEM은 파괴적·샘플링, AFM은 느리고 HAR 홀에 탐침이 못 들어가며, OCD는 스팟 평균값이라
개별 홀 정보가 없다. CD-SEM은 이미 인라인에 있고 개별 홀을 보지만 2D 출력이라, 영상에
물리적으로 새겨진 깊이 정보를 AI로 복원하면 추가 장비 없이 인라인 3D 계측이 된다.
</details>

<details><summary><b>Q2. 깊은 홀이 어둡고 테두리가 밝은 이유는?</b></summary>

이차전자(SE)는 저에너지라 표면 근처에서 생긴 것만 탈출한다. 홀 바닥의 SE는 좁은 벽을
거슬러 올라오다 흡수되어 깊을수록 어둡고(shadowing, 대전 시 심화), 경사면·모서리는
상호작용 부피가 표면과 더 겹쳐 SE 탈출이 늘어 밝다(edge effect).
</details>

<details><summary><b>Q3. 이 데이터의 "3중 어긋남"을 각각 수치로 말해 보라.</b></summary>

외형 갭(sim μ/σ 99.9/57.8 vs real 115.6/65.8), 라벨 인코딩 불일치(sim 픽셀 작을수록 깊음
vs real avg 클수록 깊음), 라벨 시프트(sim depth 평균 111±7.5 한 덩어리 vs real
108.7/118.6/128.2/138.2 4군집).
</details>

<details><summary><b>Q4. 왜 스플릿을 구조 이름 단위로 해야 하나?</b></summary>

같은 구조(base name)가 Case_1~4에 반복되고 케이스당 itr 2장이 있어, 케이스·파일 단위로
나누면 같은 구조가 train/val 양쪽에 들어가 검증 점수가 부풀어 오른다.
</details>

<details><summary><b>Q5. cal-proxy는 무엇을 재고 무엇을 못 재나? 그것을 어떤 실험이 확정했나?</b></summary>

real train에서 `avg ≈ α+β·mean(pred)`를 적합한 잔차 — 평균 수준의 real 전이력을 잰다.
평균이 풀린 뒤의 픽셀 형상 오차는 못 본다. E3(로컬 全개선, LB 5.33→5.63)이 확정했다.
</details>

<details><summary><b>Q6. EM-아핀 약지도에서 sim L1 항을 빼면 어떻게 되나? β 가드는 왜 있나?</b></summary>

real 항만 남으면 모델은 영상당 평균만 맞추면 되므로 상수 맵으로 퇴화한다. sim L1이 픽셀
형상을 고정하는 앵커다. |β|<0.1인 재적합은 예측이 무너진 상태의 기울기이므로 무시해
퇴화 루프를 막는다.
</details>

<details><summary><b>Q7. E0·E1·E5는 왜 실패했고, 하나의 문장으로 뭐라 요약하나?</b></summary>

전역 정렬·밝기 랜덤화·그 특징 재활용 모두 절대 밝기를 지우거나 왜곡했는데, 이 문제에서
절대 밝기는 깊이 신호의 주 운반자(r=−0.977)다. "밝기는 노이즈가 아니라 신호다."
</details>

<details><summary><b>Q8. itr-평균 입력이 "밝기를 보존하는 정합"인 이유는? 로컬에서 어떻게 먼저 검증했나?</b></summary>

두 노이즈 실현의 평균은 밝기 기대값을 보존하고 노이즈만 1/√2로 줄인다 — 장비의
프레임 적산과 같은 연산. 약지도 파인튜닝 epoch 0의 cal-proxy가 5.41→3.83으로 재학습
전에 이미 개선되어 가설이 로컬에서 성립한 뒤 제출했다.
</details>

<details><summary><b>Q9. σ=0.7은 어떻게 나왔나?</b></summary>

real 영상과 sim(itr-평균+가우시안 블러 σ) 영상의 방사형 파워 스펙트럼을 비교해 가장
가까워지는 σ를 탐색한 값. 감이 아니라 측정.
</details>

<details><summary><b>Q10. E8(3멤버 4.597)과 E10(6멤버 4.657)의 차이가 말해 주는 것은?</b></summary>

동일 가중 앙상블에 약한 멤버를 더하면 희석된다. 앙상블은 가설이 다른 소수의 강한 멤버를
선별하는 일이다(질>양).
</details>

<details><summary><b>Q11. 1위 솔루션의 원리와, 그것이 성립하기 위한 전제는?</b></summary>

CycleGAN으로 real화한 sim 라이브러리에서 테스트 영상과 코사인 유사도가 가장 높은 구조를
찾아 그 GT를 그대로 출력(견본 검색). 전제는 테스트가 라이브러리와 같은 구조 모집단의
재촬영이라는 것.
</details>

<details><summary><b>Q12. 확장 트랙에서 "재현됐다"고 말할 수 있는 것과 없는 것은?</b></summary>

재현: GT 구조 해독(배경/바닥 상수, 버킷↔Case), 케이스 분류기(98.7%, 테스트 분포 일치).
미재현: 교차 도메인 랭킹(site-일관성 3~5%, 랭커 3종 모두 ~6.3). 공개 1.22와의 간극은
검증 불가 요인으로 남겼다.
</details>

<details><summary><b>Q13. 실무(인라인 계측)에 옮긴다면 무엇이 더 필요한가?</b></summary>

소량의 실측 GT(TEM 크로스 캘리브레이션)로 픽셀 수준 오차를 재는 검증셋, 장비·레시피별
(α,β) 재캘리브레이션 절차, 데이터 파이프라인 스루풋(모델은 병목이 아님).
</details>

<details><summary><b>Q14. fp16으로 코사인 유사도를 계산하면 무슨 일이 생기나?</b></summary>

3,456차원 내적이 ~7.8e7까지 커져 fp16 최대값(65,504)을 넘어 오버플로우하고, 스케일을
줄여도 근사 동점의 순위가 정밀도 부족으로 뒤집힌다. float32로 계산해야 한다.
</details>

| ARDE | 종횡비가 클수록 식각 속도가 떨어지는 현상 |
| OCD | Optical CD, 산란 스펙트럼을 기하 모델로 피팅하는 광학 계측 |
| TEM/FIB | 투과전자현미경 / 집속이온빔(단면 시편 제작) |
| SPC / APC | 통계적 공정 관리 / 계측값으로 다음 공정을 보정하는 제어 |
| sim-to-real | 시뮬레이션으로 학습해 실제 데이터에 적용할 때의 분포 차이 문제 |
| 라벨 시프트 | 입력이 아니라 라벨 분포가 도메인 간에 다른 것 |
| 약지도(weak supervision) | 픽셀 GT 대신 영상당 스칼라 같은 약한 라벨로 학습 |
| EM | 잠재 파라미터 추정(E)과 모델 학습(M)을 번갈아 하는 구조 |
| Self-training / pseudo-label | 모델 예측을 라벨로 재학습. 확증 편향 위험 |
| 확증 편향(confirmation bias) | 모델의 계통 오차가 pseudo 라벨로 강화되는 현상 |
| 그룹 스플릿 | 같은 개체(구조)가 train/val에 나뉘지 않게 그룹 단위로 나누는 것 |
| cal-proxy | 아핀 캘리브레이션 후 잔차 RMSE. 이 프로젝트의 로컬 전이 지표 |
| TTA | Test-Time Augmentation. flip 등 변환 예측을 평균 |
| U-Net | 인코더-디코더 + skip connection 구조의 픽셀 예측 네트워크 |
| timm | PyTorch 사전학습 비전 백본 라이브러리 |
| 견본 검색(retrieval) | 쿼리와 가장 닮은 라이브러리 항목을 찾아 그 정답을 출력 |
| CycleGAN / WGAN-GP | 쌍 없는 도메인 변환 GAN / 그래디언트 페널티로 안정화한 GAN 손실 |
| 대조학습 / NT-Xent | positive 쌍은 가깝게, negative는 멀게 임베딩을 학습하는 방법과 그 손실 |
| site-일관성 | 같은 site의 영상들이 같은 라이브러리 키를 검색하는 비율(라벨 없는 랭킹 오라클) |
